### القسم الأول: هيكلة واجهة المستخدم (UI/UX Restructuring)
**ملاحظة صارمة للمبرمج:** واجهة التطبيق يجب أن تكون بوضع داكن (Dark Theme)، خالية تماماً من الإيموجيات، وتعتمد فقط على أيقونات (SVG) رفيعة واحترافية.

 * تقوم الشاشة بفحص الـ Token المحفوظ. إذا كان صالحاً تمر للوحة التحكم، وإذا كان منتهياً يتم محوه آلياً وتوجيه المستخدم لإعادة تسجيل الدخول دون عرض رسائل خطأ.
**الشاشة 2: المصادقة وإدارة الأرقام (Authentication)**

**الشاشة 3: لوحة التحكم المركزية (Main Dashboard)**

### القسم الثاني: أوامر صارمة للمبرمج (Developer Directives & API Mapping)
**إلى مبرمج الـ React Native:**
يُمنع منعاً باتاً تخمين أو استخدام أي مسارات (APIs) خارجية أو بروكسيات. يجب عليك استخراج الروابط، الترويسات (Headers)، وهياكل الطلبات حصرياً من الملفات المرجعية المرفقة معك (boykta.py، boykta2.py، و boykta.txt المرفق به سجلات Reqable).
**خريطة الروابط الإجبارية (API Map to Implement):**
 1. **الترويسات الأساسية (Base Headers) في كل الطلبات:**
   * يجب استخدام User-Agent: MobileApp/3.0.6 و Authorization: Bearer {token}.
 2. **الرصيد والاستهلاك (الشاشة 3):**
   * الرصيد: GET /api/v1/subscribers/main-balance/{msisdn}.
   * الباقات النشطة: GET /api/v1/subscribers/connected-products-balances/{msisdn}.
   * سجل التفعيلات (يُربط ببطاقة الاستهلاك): GET /api/v1/subscribers/subscription-history/{msisdn}.
 3. **تفعيل العروض (الشاشة 4):**
   * يتم استخراج أكواد العروض (packageCode) من PAID_OFFERS.
   * روابط التفعيل: POST /api/v1/subscribers/activate-product/{msisdn} وعروض الهز POST /api/v1/services/shake/{msisdn}.
 4. **تحويل الرصيد والإنترنت وسجلاتها (الشاشة 5):**
   * تحويل رصيد: POST /api/v1/services/flexy/credit/{msisdn}.
   * سجل الرصيد: GET /api/v1/services/flexy/history/{msisdn}?type=CREDIT_SHARE.
   * تحويل إنترنت: POST /api/v1/services/flexy/data/{msisdn}.
   * سجل الإنترنت: GET /api/v1/services/flexy/history/{msisdn}?type=DATA_SHARE.
 5. **الخدمات المجانية والدعوات (الشاشة 6):**
   * الرسائل المجانية: POST /api/v1/customer-care/bip-sms/{msisdn}.
   * إرسال دعوة: POST /api/v1/services/mgm/send-invitation/{msisdn}.
   * تفعيل المكافأة: POST /api/v1/services/mgm/activate-reward/{msisdn}.
 6. **امش واربح (الشاشة 7):**
   * التفعيل: POST /api/v1/services/walk/activate-reward/{msisdn} (Code: GIFTWALKWIN2GO).

### القسم الرابع: البنية التحتية المتقدمة (Kotlin Native, Security & CI/CD)
**إلى مبرمج الـ Kotlin (Android Developer):**
التطبيق يجب أن يُبنى كـ Native Android App باستخدام لغة Kotlin و Jetpack Compose لواجهة مستخدم حديثة وسريعة. يُمنع استخدام أي منصات هجينة.
**1. نظام الإعلانات المدمج (Start.io Monetization)**
 * **المعرف الرسمي (App ID):** يجب استخدام المعرف 207841284 لتهيئة حزمة StartApp SDK في ملف MainActivity.kt.
 * **آلية الظهور الذكية:** يتم تحميل الإعلان البيني (StartAppAd.loadAd) في الخلفية أثناء قيام المستخدم باختيار العرض.
 * عند تلقي استجابة (200 أو 201) من API جازي بنجاح العملية، تظهر نافذة (Modal) النجاح ومتابعة الصفحة. بمجرد أن يضغط المستخدم "حسناً" أو يغلق النافذة، يتم فوراً استدعاء الإعلان startAppAd.showAd().
**2. التشفير والحماية الصارمة (ProGuard / R8 & String Encryption)**
لمنع أي مخترق من تفكيك الـ APK (عبر APKTool) وتغيير اسم التطبيق، أو سرقة روابط الـ API، يجب تفعيل جدار الحماية التالي في ملف build.gradle.kts (app level):
 * تفعيل minifyEnabled true و shrinkResources true لحذف أي أكواد غير مستخدمة وتشفير أسماء الكلاسات (Classes).
 * **إخفاء الروابط (API Hiding):** يجب ألا تُكتب الروابط والترويسات (Headers) كنصوص واضحة (Plain Text). استخدم مكتبة تشفير (مثل StringCare أو تشفيرها باستخدام C++ NDK) بحيث يتم فك تشفيرها فقط في الذاكرة الحية وقت الاتصال.
 * إضافة قاعدة proguard-rules.pro صارمة لتعمية الكود بالكامل، مما يظهر الكود على شكل أحرف عشوائية (a, b, c) عند محاولة الهندسة العكسية.
**3. هندسة فصل المعماريات (ABI APK Splits)**
للحصول على تطبيق "فائق الخفة" ولتجنب رفع تطبيق بحجم كبير، يجب فصل بناء الـ APK حسب معمارية معالج الهاتف. في ملف build.gradle.kts، يجب إضافة الكتلة التالية:
```kotlin
android {
    // ...
    splits {
        abi {
            isEnable = true
            reset()
            include("armeabi-v7a", "arm64-v8a") // بناء نسختين منفصلتين
            isUniversalApk = false // إلغاء البناء المدمج الثقيل
        }
    }
}

```
هذا سينتج تطبيقاً صغيراً جداً (قد لا يتجاوز 4 ميغابايت) مخصصاً لمعمارية arm_v7a وآخر لمعمارية arm64_v8a، لتقوم برفعها بشكل منفصل.
**4. دور Replit والتكامل مع GitHub Actions (CI/CD)**
 * **دور Replit:** سيُستخدم حصرياً لكتابة الكود، التحقق من خلوه من الأخطاء النحوية (Linting)، والتأكد من ترتيب الملفات والمجلدات.
 * **دور GitHub Actions:** سيقوم الخادم السحابي ببدء عملية الـ Gradle Build المعقدة، حقن مفتاح التوقيع (Keystore)، واستخراج ملفات الـ Release APKs النهائية والمشفرة.
 * يجب إنشاء ملف المسار .github/workflows/android-build.yml في جذر المشروع ليحتوي على تعليمات بناء Android CI.
